# Configuration model

[← Back to index](./README.md)

---

## 1. Hierarchy

```
Configuration Template            — one per project, identified by a template name
  └─ Template version             — published from /hat-admin; defines WHAT can be configured
       └─ Variant                 — A/B tests, seasonal versions, staging
            └─ Site node          — a node in the site tree; settings cascade to descendants
                 └─ Container     — e.g. HomePage1, DetailExtendedWidgets1, headerWidgets
                      └─ Box      — box_top, box_left, box_middle, box_right, box_bottom
                           └─ Ordered list of widgets, each with its own parameters
```

Two distinctions matter:

- **Template version vs. configuration values.** A version describes the available modules and their
  fields; the values are set per node and variant. Publishing a new version never overwrites values.
- **Node cascade.** Product owners configure a layout once on a parent category, and child
  categories inherit it until they override it.

## 2. Anatomy of a configuration file

Every `*WebsitesConfig.ts` follows the same shape:

```ts
export let SomethingWebsitesConfig = {
    sections: [],          // global settings sections contributed by this file
    defaultParams: {},     // default values for those sections
    paramsDescription: {}, // field descriptions for those sections
    modules: {             // widgets contributed by this file
        something_wdg: {
            name: "Display name in Websites Manager",
            description: "",
            defaultParams: { /* initial values for a new widget instance */ },
            paramsDescription: { /* how each field is rendered */ },
        },
    },
};
```

`generateConfig()` deep-merges every registered file into one structure, concatenating arrays, sorts
modules by display name, and substitutes the list of all available module keys wherever a modules
list placeholder appears (this is what populates the widget picker inside a grid box).

## 3. Shared widget parameters

From `AbstractWebsitesWidgetConfigParamsDescription` — present on every widget:

| Parameter | Type | Default | Purpose |
|---|---|---|---|
| `widgetType` | textfield (required) | — | Resolves the component; not meant to be edited |
| `platformDesktop` | checkbox | `true` | Render on desktop |
| `platformMobile` | checkbox | `true` | Render on mobile |
| `customClass` | textfield | `""` | Extra CSS class |
| `customPosition` | select | `none` | `none`, `left`, `center`, `right` |
| `customWidth` | select | `none` | `none`, `1` … `12` |

## 4. Grid container configuration

Generated by `GridHelper_generateGridConfig(configKey, title, containerCount)`. Each container
contributes:

| Field | Type | Purpose |
|---|---|---|
| `container_html_tag` | select (`div`, `section`, `aside`) | Wrapping element |
| `container_classes` | textfield | Custom CSS classes |
| `container_hide` | checkbox | Hide the whole container on this node |
| `box_top`, `box_left`, `box_middle`, `box_right`, `box_bottom` | modules list | The ordered widget list for each box |
| `box_*_size` | select (1–12) | Box width |
| `box_*_html_tag` | select (`div`, `section`, `aside`) | Box element |

Header and footer containers use the alternative box names `widgets_above_content`,
`widgets_middle_content`, `widgets_below_content` / `widgets_under_content` and
`widgets_additional_box`.

## 5. Global settings sections

These are site-wide settings, not per-widget. They appear as their own sections in Websites Manager.

### General

| Field | Purpose |
|---|---|
| Language code | Drives locale, date formatting and translations |
| Site name | Used across SEO, Open Graph and structured data |
| Site description | Default description fallback |
| Site contact number | Feeds the `Organization` structured data |
| Site logo | Feeds SEO and structured data |
| Homepage URL | Canonical base for structured data |
| Default image on page | Fallback image for Open Graph and teasers |

### SEO

| Group | Fields |
|---|---|
| SEO general | Default author name and e-mail (used when an article has no author), homepage node IDs |
| Titles & descriptions | Templates for home, list, tag, search, author, detail and other pages — each with a separate paginated variant |
| Languages | Supported languages (code, alternate role code name, default flag) and custom alternates |
| RSS defaults | Feed type, item limit, excluded flags, excluded category IDs |
| Open Graph | Desktop and mobile image sizes |
| Meta data | Custom meta tags scoped by site content type |
| Content link settings | Domain whitelist toggle, whitelisted domains and their `rel` attributes |

Title and description templates support bracket variables resolved by
`SeoHelper_replaceBracketVariables`.

### Developer settings

| Group | Fields |
|---|---|
| General | Global date format, service time zone, extended relative date formats (same day, last / next day, last / next week, same else), toggle to use the extended format by default |
| Detail | Text decorators (match pattern → replacement), global custom teasers, main category UUID, head widgets box, title addon used as the display title |
| Links | Link replacer rules (role → replacement) |

### Translations

A list of `language` / `source` / `translation` triples, read at runtime through
`TranslationProvider.translate`.

## 6. Widget-level caching

Most content widgets expose a `cacheTTL` field in seconds. Combined with tag-based invalidation,
this gives per-widget freshness control:

| Widget kind | Typical TTL |
|---|---|
| News list on a homepage | 30–120 s |
| Article body and metadata | 300–900 s (purged by webhook on publish) |
| Header, footer, menu, logo | 1800–3600 s |

Publishing content in the CMS triggers a webhook that purges every cache entry tagged with that
content's UUID, so a long TTL does not delay editorial updates.

## 7. Environment flags that affect behaviour

| Variable | Effect |
|---|---|
| `CONFIGURATION_TEMPLATE_NAME` | Target template for `/hat-admin` publishing; required for the admin page to work |
| `DEEP_PAGINATION_ENABLED` | `1` removes the 1000-item offset cap in list pagination and SEO prev/next links |
| Development mode | Enables `/hat-admin`, relative links in `RingLink`, and diagnostic placeholders instead of silent empty output |
